# ADR-0034: Drop Minecraft 1.20.1 support

Status: accepted

## Context

The `versions/1.20.1` module kept breaking on version-coupled seams: identifier type naming,
save-data format, mixin targets and signatures, damage/hurt APIs, client screen and HUD
signatures. Every port of a gameplay change had to be re-ported against 1.20.1's mappings,
and its melee hook fires from a `LivingEntityMixin` (no after-damage event on that version)
which diverges from the after-damage event used by 1.21.1 and 26.3.

The decision core lives once in `common` and is version-agnostic, but the 1.20.1 adapter
surface — mixins, networking, damage hooks, client widgets — is not shared. Keeping a
third module green cost a full port per change with no gameplay difference: 1.20.1's rules
are identical to 1.21.1 and 26.3 by ADR-0033's design.

## Decision

Remove the `versions/1.20.1` module entirely: directory, sources, tests, resources,
`build.gradle`, `gradle.properties` and its `:mc1201` Gradle project. Support 1.21.1 and
26.3 only.

- `settings.gradle` no longer includes `:mc1201`.
- Tooling defaults (`mixin-targets.sh`, `mc-jar.sh`, `deployClient`) reference only
  `versions/1.21.1` and `versions/26.3`; `mixin-targets.sh` no longer has a default that
  resolves to 1.20.1.
- Metadata, docs, README, project description, AGENTS.md and CHANGELOG list 1.21.1 and
  26.3 only; 1.20.1 and 1.21.11 are both marked unsupported.

## Consequences

- Players on 1.20.1 can no longer install the mod; reports against 1.20.1 close as
  wontfix, moving to 1.21.1.
- Save data is version-agnostic (only the class choice is persisted), so a choice made on
  a 1.20.1 jar carries over when the player moves to 1.21.1.
- One Fabric module per remaining version is unchanged; adding a later version is still a
  new directory plus a port, not a fork.
